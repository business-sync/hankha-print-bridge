# 1.14.1 — a paused USB print queue is resumed automatically

**Drop-in upgrade** (`relay.json` / `printers.json` untouched). Affects macOS and Linux printers
that go through the system print queue (the "USB" driver). Network, serial and Windows printers
and the container build behave exactly as in 1.14.0.

## What was wrong

- A USB printer that is switched off, unplugged, or left behind when the Mac sleeps makes CUPS
  disable ("pause") its queue. CUPS does not enable it again when the printer comes back, and
  `lp` keeps accepting jobs into a disabled queue.
- The bridge therefore reported every bill as sent while nothing came out, until someone ran
  `cupsenable` by hand or pressed Resume in the macOS print queue window. To the operator this
  looked like a printer that disconnected and never reconnected.

## What changed

- Before sending to a CUPS queue the bridge asks `lpstat -p <queue>`. If the queue is disabled it
  runs `cupsenable <queue>` and then sends the job.
- Both commands are limited to 2 s. A failed check or a refused `cupsenable` never blocks the
  job: it is logged and the job goes to `lp` exactly as before.
- New log events: `spooler.queue_resumed` and `spooler.queue_resume_failed` (with the reason).

## Notes for operators

- **Late prints:** CUPS holds jobs it accepted while the queue was paused and prints them when the
  queue resumes, as Resume does in the macOS print window. A bill that was reported as sent during
  an outage can therefore print late. Clear stale jobs with `cancel -a <queue>` if that is not wanted.
- **Permissions:** `cupsenable` needs CUPS administration rights. The macOS `.pkg` install runs as
  a system service and has them. The `.dmg` agent runs as the signed-in user, who has them on macOS
  when they are an administrator; on Linux they must be in the `lpadmin` group. Without the right,
  look for `spooler.queue_resume_failed` in the log and resume the queue by hand as before.
- **Scope:** this heals the bridge-to-printer leg only. A printer paired directly in the POS
  terminal over WebUSB, Web Serial or Bluetooth is reconnected by the POS terminal itself.

# 1.13.2 — the bridge no longer disconnects by itself

**1.13.2 is a drop-in upgrade.** `relay.json` and `printers.json` are kept as they are; an upgraded
bridge does not re-enroll and does not appear twice in the POS.

From this version the bridge stops being connected only when the user removes it. Everything else
is retried until it works.

## What was wrong

- **One 401 ended the connection for good.** Any "token rejected" answer — including one from a
  proxy in front of the API, or a 403 from a firewall — stopped the relay loop. The POS showed
  *Printing Connection: disconnected* until someone paired the computer again by hand.
- **A dead network link looked connected.** If the connection dropped without being closed (Wi-Fi
  drop, router NAT timeout, sleep and wake) the bridge kept waiting on it for minutes, so the POS
  showed it online while no print job could arrive.
- **A half-written `relay.json` looked like "never paired".** A power cut during a save could leave
  the credential file unreadable, and the bridge then announced itself as a new computer.

## What changed

- A rejected token is retried every 30 s to 5 min instead of ending the loop. Pairing again from
  the local page takes effect immediately, with no restart. A 403 is treated as a network fault, not
  as a rejected credential.
- The websocket pings the server and reconnects after 45 s of silence.
- `relay.json` is written atomically and the previous copy is kept as `relay.json.bak`, which is
  used if the main file cannot be read.

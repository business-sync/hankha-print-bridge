# 1.14.0 — a silently dead connection is now detected and replaced

**Drop-in upgrade** (`relay.json` / `printers.json` untouched). Works best with a backend that
acknowledges heartbeats; against an older backend it behaves as 1.13.2.

## What was wrong

- A websocket could stay "connected" while the server stopped delivering jobs. Transport pongs
  are answered by any proxy, so the bridge never noticed, and the HTTP heartbeat kept the POS
  showing it online while nothing printed until the service was restarted by hand.
- A 400/403/408/429 on the websocket upgrade (proxy, WAF, rate limit) disabled the websocket for 30
  minutes as if the route did not exist.
- Two processes sharing one token replaced each other about once a second.
- Nothing restarted a bridge that was running but unable to reach the cloud.
- A rejected heartbeat was invisible, and its response body pinned a pooled connection.

## What changed

- The server acknowledges every `hello`/`heartbeat`; no ack for ~95 s replaces the socket
  (`relay.ws.ack_timeout`). Only enforced once the server has acked at least once.
- Only 404/405/426 mean "websocket unsupported"; other upgrade failures back off and retry.
- Rapid accept-then-close sessions back off with jitter (`relay.ws.flap`).
- Watchdog: disconnected continuously for 15 min while paired → exit 1 so launchd / Task Scheduler /
  systemd / k8s restart the bridge (`relay.watchdog.restart`). `PRINT_BRIDGE_WATCHDOG_MINUTES=0` disables.
- Rejected heartbeats are logged (`relay.heartbeat.rejected`) and their bodies released.
- The relay starts only after the HTTP port is bound, so a duplicate copy no longer announces itself.

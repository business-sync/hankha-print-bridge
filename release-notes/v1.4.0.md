Local helper that prints POS receipts and labels on a venue's own hardware — over the network
(ESC/POS-over-TCP), a USB print queue, or a serial/Bluetooth port. It runs on a venue PC, not
inside the POS terminal's PWA, because a browser cannot open any of those. It also dials out to
the cloud API, so a phone can print through it without reaching the LAN. Install it on **every
till**, not on one shared PC.

**1.4.0 is a drop-in upgrade.** `POST /print` with `{ip, port, payload_base64}` is unchanged and
still answers `{ok:true}`, so an existing till keeps working with no configuration at all — the
new registry is opt-in. Enrollment survives: `relay.json` is kept, and an upgraded bridge does not
re-enroll or appear as a second entry in the POS.

## What's new in 1.4.0

**USB and Bluetooth printers.** The bridge was network-only; it now speaks three transports.
`usb` goes through the operating system's own print spooler in raw mode — `lp -o raw` on
macOS/Linux, `winspool`'s `WritePrinter` on Windows — so you get the driver the vendor already
installed, network queues for free, and no elevated USB permissions. `serial` writes straight to
the character device, **and that is also how Bluetooth works**: pair the printer in the OS's own
Bluetooth settings, where the PIN prompt belongs, and it turns up as `/dev/cu.Something-SPP`,
`/dev/rfcomm0`, or a COM port. (There is no BLE path — a GATT-only printer needs a native
Bluetooth stack the OS cannot expose as a tty.)

**A printer registry.** `printers.json` in the state directory names each printer once — id,
transport, type, language, paper geometry — and a job can then just say which one it wants. Read
it with `GET /printers`, replace it with `PUT /printers` (a rejected `PUT` changes nothing and
returns *every* problem at once), or look at it from the command line:

```
hankha-print-bridge --list-printers
hankha-print-bridge --test-print counter
```

A non-network printer may still declare an `address`. That is what lets a cloud job — which
carries only a target ip and port — reach a USB printer, with no change on the server or in the
POS.

**The bridge renders the ticket.** A job can now be a receipt or a label document instead of
pre-cooked bytes: `text`, `columns`, `rule`, `feed`, `image`, `barcode`, `qr`, `cut`, `drawer` for
a receipt; `text`, `barcode`, `qr`, `image`, `box`, `line` on a label canvas. It renders to
**ESC/POS, ZPL, TSPL or EPL2**, and barcodes and QR are encoded by the printer's own firmware, so
this still ships with zero runtime dependencies. A receipt sent to a label printer is refused
rather than clipped at the bottom of a 30 mm label.

**Lao text is refused, not silently dropped.** None of these printers has a Lao code page or a
resident Lao font. The renderer takes ASCII plus a table of equivalents (`₭` → `LAK`) and answers
**422 naming the offending characters**. The old code dropped what it could not encode, so
`2x ເຂົ້າຜັດໄກ່` printed as `2x ` with no error anywhere. Send Lao as a pre-rendered 1-bit `image`
element — exactly what the POS terminal already produces.

**A print queue that survives a restart.** Jobs are spooled to disk, printed **sequentially per
printer and concurrently across printers** (several kitchen stations usually share one physical
printer, and two interleaved writes produce one shredded ticket), and only retried when they
*provably* did not print — anything that failed after the channel opened is terminal, because
retrying it is how a customer ends up holding two bills. With `ttl_s` set, a job retries until its
deadline and is then **dropped rather than printed late**. Job ids are deduplicated across
restarts, so a redelivered job is answered, never reprinted.

**Find printers, and see whether they are up.** `POST /discover` returns everything this machine
can see across all three transports — and says which transports are usable at all, because "no USB
printers" and "this machine cannot see USB printers" send an operator looking for very different
things. `GET /status` adds per-printer online/offline with latency and the queue depth by state;
`POST /probe` and `POST /scan` are unchanged in spirit and now report why a host failed.

**A status page at <http://localhost:9200>.** Once installed the bridge is a launchd daemon or a
scheduled task with no window, and typing its address into a browser used to return
`{"ok":false,"reason":"not-found"}` — which reads as "the thing I just installed is broken". It
now serves a page showing which machine is answering, which printers are online, the queue, the
recent jobs with the reason each one failed, and the address another till should be pointed at. It
is not a configuration screen; the one thing it can do to a printer is send the test slip.

**Cloud printing got out of its own way.** The relay's long-poll no longer prints inline — it
enqueues — so a printer taking four seconds to answer no longer stops the bridge fetching *any*
cloud work for those four seconds. A WebSocket channel is implemented behind
`PRINT_BRIDGE_RELAY_TRANSPORT` and falls back to the long-poll automatically; the server half is
not built yet, so `auto` behaves exactly like `poll` today.

**Operational knobs.** `PRINT_BRIDGE_MAX_ATTEMPTS`, `PRINT_BRIDGE_SEND_TIMEOUT_MS`,
`PRINT_BRIDGE_SYNC_TIMEOUT_MS`, and structured logging via `PRINT_BRIDGE_LOG_FORMAT=json` /
`PRINT_BRIDGE_LOG_LEVEL`. An installed bridge still takes its configuration from the service
definition — `EnvironmentVariables` in the launchd plist, `bridge.env` on Windows.

## Which download

| File | Use it for |
| --- | --- |
| `hankha-print-bridge-1.4.0-macos.dmg` | **Most Macs.** Drag to Applications, open it once. Registers a per-user LaunchAgent that starts at login. No administrator password. |
| `hankha-print-bridge-1.4.0-macos-universal.pkg` | Managed fleets / MDM. Installs a system LaunchDaemon that starts at **boot** for every user. Costs one admin password. |
| `hankha-print-bridge-1.4.0-windows-x64-setup.exe` | **Most Windows tills.** Starts immediately and on every boot; uninstall from Settings → Apps. |
| `hankha-print-bridge-1.4.0-windows-x64.zip` | Scripted rollout — unzip and run `.\install.ps1` from an elevated PowerShell (`-Lan` also serves other terminals on this network). |

On macOS, install **one** of the two — they both want port 9200.

## These builds are unsigned

- **macOS**: the first open reports an unidentified developer. Right-click the app or package
  and choose **Open**, or clear the flag first:
  `xattr -dr com.apple.quarantine "/Applications/Hankha Print Bridge.app"`
- **Windows**: SmartScreen shows "Windows protected your PC" — **More info** → **Run anyway**.

# 1.11.0 — the whole page speaks five languages

The bridge's page at <http://localhost:9200> is opened by whoever is standing at the till. Two
screens on it were already translated — the pairing screen from 1.9.0 and the "This computer" card
from 1.10.0 — and everything behind them was English: the printer table, the job history, every
banner, every error, the find-printers sweep, the token gate. A Lao café owner who paired a
printer in Lao and restarted the bridge in Lao then hit English the moment anything went wrong,
which is the one moment the words matter.

All of it is now in **English, ລາວ, ไทย, 中文 and Tiếng Việt** — 245 phrases, 1,225 translated
values, with the two existing screens folded into the same table.

**1.11.0 is a drop-in upgrade.** `relay.json` and `printers.json` are untouched, no bridge
re-enrolls, and nothing about printing changed. This release is the page only.

## Picking a language

There are two pickers and one choice. The pairing screen keeps its row of language names — it has
the room, and someone pairing a printer has nothing else to read. Behind it, the diagnostics page
gets a compact picker in the header. Both are rebuilt together, so neither can offer a language
the page is not already in.

The choice is remembered in the browser, and on a first visit the page follows the till's own
language rather than defaulting to English. `<html lang>` is updated with it, so a screen reader
pronounces the page correctly and the clock beside each job is formatted for the same locale the
words are in — `lo-LA` for Lao, `vi-VN` for Vietnamese.

**Switching language redraws everything immediately.** Each section on this page caches a
signature of what it last drew and repaints only when that signature moves, and none of those
signatures contained the language — so without an explicit reset, the tables, banners and job rows
would have kept the old words until their *data* happened to change, which on a healthy bridge
with a settled screen is never.

## What is deliberately still in English

Anything that is a fact rather than a sentence: printer names as they are written in
`printers.json`, addresses, file paths, the version, a transport kind, `escpos`/`receipt`, and the
`detail` and `hint` strings the bridge itself returns. A translated copy of a printer name would
not match the name the operator has to type, and translating a path helps nobody. The CLI is also
unchanged — it is read over SSH by whoever installs the bridge.

The `<noscript>` block cannot be reached by a script, so it carries all five languages as markup
instead of being switched.

## Under the hood

The strings now live in one file, `src/page-i18n.ts`, as an ordinary TypeScript object that all
three screens read. Previously each screen owned a private table, so a phrase had to be found in
two places and a sixth language would have to be added twice.

Keeping them out of the page's template literals matters more than it sounds. **A stray backtick
in that source has stopped this app starting twice**, and inside a literal every apostrophe and
dash has to be written as a `\uXXXX` escape — a rule nobody applies reliably to a thousand lines
of Lao and Vietnamese. Here the text is written as the real characters, and it is serialised into
the page safely: a backtick, a `${` or a `</` inside any translation is neutralised on the way in,
so a translation cannot end the literal it sits in or close the `<script>` element around it.

Four checks now run on every build, because each of these failures is silent rather than loud:

- **A key must exist in all five languages.** A missing one is not a crash — the page falls back
  to English — so a Lao till would simply show one English sentence among the Lao ones, and only
  someone who reads Lao would ever notice.
- **Every language of a phrase must carry the same placeholders.** Placeholders are filled by
  name, not position, because the count leads the sentence in English and trails it in Lao. A
  translation that dropped the number renders a literal `{n}` on screen in four languages.
- **The embedded table cannot break out of its script**, proved by parsing it back and comparing
  it to the source object rather than by looking for characters that are merely absent today.
- **The pairing and service rows keep their prefixes** — those two screens are nothing *but* these
  strings, so a row that lost its prefix would render as blank space.

The existing backtick guard now covers this file's own literals too.

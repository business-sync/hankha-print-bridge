Local LAN helper that forwards POS print jobs to a network (ESC/POS-over-TCP) printer. It runs
on a venue PC — not inside the POS terminal's PWA, because a browser cannot open a raw TCP
socket itself. Install it on **every till**, not on one shared PC.

## What's new in 1.3.0

**Cloud relay — printing from a device that never touches the shop network.** The bridge now
dials *out* to the Hankha API and long-polls for work, so a phone, a tablet, or a till on mobile
data can print through it. No inbound port, no TLS certificate on the shop PC, no NAT traversal,
and identical behaviour on iOS and Android. Enroll with a code from **POS Settings → Printing**:

```
hankha-print-bridge --enroll <code>
```

**A bridge identity that survives restarts and upgrades.** The install id and its relay
credential are kept in `relay.json`, so a reboot no longer re-enrols and mints a fresh bridge
row — no more choosing between a dozen identical "Counter PC" entries. Set
`PRINT_BRIDGE_STATE_DIR` to keep that file somewhere durable when running in a container.

**Online the moment it connects.** The heartbeat now reports immediately instead of waiting out
the first 30-second interval, so a freshly started bridge appears in the POS straight away.

**LAN security: bearer token and optional TLS.** `PRINT_BRIDGE_TOKEN` requires
`Authorization: Bearer <token>` on every route except `/health`. The shipped install binds
`127.0.0.1`, where the OS is the boundary — set a token whenever the bridge binds `0.0.0.0`
(a shop box, a container), or anything on the venue Wi-Fi, guest phones included, can drive the
printers. `PRINT_BRIDGE_TLS_CERT` + `PRINT_BRIDGE_TLS_KEY` serve HTTPS if you bring your own
certificate.

**Container and Kubernetes deployment.** Dockerfile, docker-compose, a systemd unit and k8s
manifests, with CI publishing `ghcr.io/business-sync/hankha-print-bridge`.

## Which download

| File | Use it for |
| --- | --- |
| `hankha-print-bridge-1.3.0-macos.dmg` | **Most Macs.** Drag to Applications, open it once. Registers a per-user LaunchAgent that starts at login. No administrator password. |
| `hankha-print-bridge-1.3.0-macos-universal.pkg` | Managed fleets / MDM. Installs a system LaunchDaemon that starts at **boot** for every user. Costs one admin password. |
| `hankha-print-bridge-1.3.0-windows-x64-setup.exe` | **Most Windows tills.** Starts immediately and on every boot; uninstall from Settings → Apps. |
| `hankha-print-bridge-1.3.0-windows-x64.zip` | Scripted rollout — unzip and run `.\install.ps1` from an elevated PowerShell (`-Lan` also serves other terminals on this network). |

On macOS, install **one** of the two — they both want port 9200.

## These builds are unsigned

- **macOS**: the first open reports an unidentified developer. Right-click the app or package
  and choose **Open**, or clear the flag first:
  `xattr -dr com.apple.quarantine "/Applications/Hankha Print Bridge.app"`
- **Windows**: SmartScreen shows "Windows protected your PC" — **More info** → **Run anyway**.
